# Backend

## Возможности

- роли `student`, `teacher`, `moderator`;
- создание пользователей модератором;
- редактируемая преподавателем подпись предмета;
- серверные сессии в защищённой cookie;
- интервалы доступности преподавателей до 24 часов;
- длительности занятий 15, 30, 45 и 60 минут;
- расчёт свободного времени с шагом 10 минут;
- ручное подтверждение заявок;
- самостоятельная запись ученика преподавателем или модератором;
- запрет пересечений занятий преподавателя и ученика на уровне PostgreSQL;
- индивидуальные для каждого ученика ссылки Teams, Zoom, Яндекс Телемост, Google Meet, СберJazz и произвольные ссылки;
- уникальность непустой ссылки между аккаунтами учеников на уровне PostgreSQL;
- журнал административных действий;
- структурированные логи `zerolog` и журналирование всех запросов PostgreSQL без параметров;
- HTTP rate limiting, лимит параллелизма, таймауты и ограничение тела запроса;
- отдельное ограничение попыток входа через Redis.

## Запуск локально

1. Скопировать `build/.env.example` в `build/.env` и заменить тестовые значения.
2. Запустить PostgreSQL, Redis, миграции и API:

   ```sh
   docker compose --env-file build/.env -f build/docker-compose.backend.yml up --build
   ```

3. Однократно создать первого модератора:

   ```sh
   docker compose --env-file build/.env -f build/docker-compose.backend.yml \
     --profile bootstrap run --rm bootstrap
   ```

API слушает `127.0.0.1:8080`. В production перед ним должен находиться reverse proxy
с HTTPS. `COOKIE_SECURE=true` требует HTTPS; для локального запуска Go-процесса без
reverse proxy установите `APP_ENV=development` и `COOKIE_SECURE=false`.

## Основные переменные окружения

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `DATABASE_URL` | Подключение PostgreSQL | обязательна |
| `REDIS_ADDRESS` | Адрес Redis | `redis:6379` |
| `HTTP_ADDRESS` | Адрес HTTP-сервера | `:8080` |
| `ALLOWED_ORIGINS` | Допустимые Origin для изменяющих запросов | пусто |
| `TRUSTED_PROXY_CIDRS` | Прокси, от которых принимается `X-Forwarded-For` | пусто |
| `RATE_LIMIT_RPS` | Запросов в секунду на IP | `10` |
| `RATE_LIMIT_BURST` | Допустимый кратковременный всплеск | `20` |
| `MAX_RATE_CLIENTS` | Максимум IP в памяти limiter | `10000` |
| `MAX_IN_FLIGHT` | Максимум одновременно обрабатываемых запросов | `100` |
| `MAX_LOGIN_IN_FLIGHT` | Максимум одновременных Argon2-проверок пароля | `4` |
| `MAX_BODY_BYTES` | Максимальный размер HTTP-тела | `1048576` |
| `REQUEST_TIMEOUT` | Таймаут прикладного запроса | `10s` |
| `LOGIN_ATTEMPTS` | Попыток входа за окно | `5` |
| `LOGIN_WINDOW` | Окно ограничения входа | `15m` |

## HTTP API

Все даты передаются в RFC 3339 и сохраняются в UTC. После входа используется cookie.
Для `POST /bookings` обязателен заголовок `Idempotency-Key`.

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `POST /api/v1/auth/login` | публичный | Вход |
| `POST /api/v1/auth/logout` | авторизованный | Выход |
| `POST /api/v1/auth/password` | авторизованный | Смена своего пароля |
| `GET /api/v1/me` | авторизованный | Текущий пользователь |
| `PATCH /api/v1/me` | авторизованный | Изменить своё имя и подпись предмета преподавателя |
| `GET /api/v1/teachers` | авторизованный | Активные преподаватели |
| `GET /api/v1/students` | преподаватель, модератор | Активные ученики |
| `GET /api/v1/teachers/{id}/availability` | авторизованный | Интервалы доступности |
| `GET /api/v1/teachers/{id}/slots` | авторизованный | Свободные варианты записи |
| `POST /api/v1/availability` | преподаватель, модератор | Создать непересекающиеся части доступности |
| `DELETE /api/v1/availability/{id}` | преподаватель, модератор | Удалить свободный интервал |
| `GET /api/v1/bookings` | авторизованный | Доступные пользователю занятия |
| `POST /api/v1/bookings` | авторизованный | Создать заявку или занятие |
| `POST /api/v1/bookings/{id}/confirm` | преподаватель, модератор | Подтвердить заявку |
| `POST /api/v1/bookings/{id}/reject` | преподаватель, модератор | Отклонить заявку |
| `POST /api/v1/bookings/{id}/cancel` | авторизованный | Отменить заявку или занятие |
| `GET /api/v1/bookings/{id}/conference-links` | участник занятия | Ссылки подтверждённого занятия |
| `GET /api/v1/students/{id}/conference-links` | сам ученик, преподаватель, модератор | Доступные ссылки или настройки ссылок ученика |
| `POST /api/v1/students/{id}/conference-links` | преподаватель, модератор | Добавить пользовательскую ссылку ученика |
| `PATCH /api/v1/students/{id}/conference-links/{linkID}` | преподаватель, модератор | Изменить ссылку ученика |
| `DELETE /api/v1/students/{id}/conference-links/{linkID}` | преподаватель, модератор | Удалить пользовательскую ссылку ученика |
| `GET /api/v1/admin/users` | модератор | Все пользователи |
| `POST /api/v1/admin/users` | модератор | Создать пользователя |
| `PATCH /api/v1/admin/users/{id}` | модератор | Изменить профиль или активность |
| `POST /api/v1/admin/users/{id}/reset-password` | модератор | Выдать временный пароль |

Ученик может запросить ссылки только для собственного аккаунта. В ответ попадают
только активные ссылки с заполненным адресом; преподаватель и модератор получают
полный список настроек выбранного ученика.

`POST /api/v1/availability` не изменяет существующие интервалы и занятия. Запрошенный
диапазон разбивается вокруг пересечений, а ответ содержит созданные части в `items`
и пропущенные диапазоны в `skippedRanges`. Для слишком короткой части используется
причина `too_short`, для пересечения — `overlap`.

## Защита от DoS и DDoS

Middleware ограничивает злоупотребление ресурсами приложения, но не заменяет сетевую
DDoS-защиту. Перед production-сервером необходим reverse proxy или сервис провайдера,
который ограничивает соединения и блокирует объёмный трафик до VPS.

`X-Forwarded-For` используется только тогда, когда непосредственный адрес подключения
входит в `TRUSTED_PROXY_CIDRS`. Это предотвращает обход rate limit поддельным заголовком.

## Логирование

Каждая операция pgx журналируется централизованным tracer-ом. Аргументы SQL намеренно
исключены, чтобы пароли, идентификаторы сессий и персональные данные не попадали в логи.
Записываются текст параметризованного SQL, продолжительность, результат и ошибка.

События запуска и остановки сервиса и каждый HTTP-запрос также записываются через
`zerolog`. В production используется JSON, в development — читаемый console-формат.

## Миграции

Миграции находятся в `backend/migration` и применяются `go-migrate`. Первая миграция
создаёт расширение `btree_gist`, необходимое для ограничений пересекающихся интервалов.
